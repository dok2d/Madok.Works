# Аутентификация и роли

## Локальная аутентификация

При первом запуске приложение предлагает создать администратора. После этого вход осуществляется через форму логина.

### Сессии

- Cookie-based сессии со сроком жизни 90 дней
- Токен сессии — случайная строка длиной 64 символа
- HttpOnly cookies для защиты от XSS
- Автоматическая очистка просроченных сессий (ежечасно)

### Хеширование паролей

Пароли хешируются алгоритмом PBKDF2-HMAC-SHA256:
- 100 000 итераций
- 32-байтная случайная соль

## Роли

| Роль       | Возможности |
|------------|-------------|
| **Admin**  | Полный доступ: управление пользователями, колонками, эпиками, тегами, настройками Telegram, экспорт/импорт |
| **User**   | Создание, редактирование, удаление задач; комментарии; подписки; изменение своего пароля |
| **Read-only** | Просмотр доски и задач; получение уведомлений |

### Управление пользователями (Admin)

Администратор может:

- Создавать новых пользователей с выбором роли
- Изменять роль существующего пользователя
- Сбрасывать пароль пользователя
- Удалять пользователей

Ограничения: администратор не может изменить собственную роль и не может удалить самого себя.

## Двухфакторная аутентификация (2FA / TOTP)

2FA включается каждым пользователем по желанию и настраивается в разделе **Настройки → Аккаунт**.

### Подключение

1. Откройте Настройки → Аккаунт и начните подключение 2FA
2. Сервер возвращает `otpauth://`-ссылку (и сам секрет) — добавьте её в приложение-аутентификатор (Google Authenticator, Aegis, FreeOTP и др.), отсканировав QR-код или введя секрет вручную
3. Подтвердите подключение, введя текущий 6-значный код из приложения
4. Сервер выдаёт одноразовые **коды восстановления** — сохраните их в надёжном месте; каждый код срабатывает один раз, если вы потеряете доступ к аутентификатору

### Вход с 2FA

При включённой 2FA вход состоит из двух шагов:

1. Пользователь как обычно отправляет имя пользователя и пароль
2. Ответ на вход возвращает `{ "totp_required": true }` вместо создания сессии
3. Клиент повторяет запрос с кодом: `{ "code": "123456" }` (действующий TOTP-код или код восстановления)

## Сброс пароля из CLI (закрытые сети)

В изолированной/закрытой сети Telegram-сброс пароля недоступен. Это важно и сразу
после **восстановления из бэкапа**: экспорт не содержит хэши паролей — все
восстановленные пользователи (включая админов) остаются без рабочего пароля.

Сбросить (или создать) администратора прямо из CLI, против той же БД, что
использует приложение:

```bash
# через обёртку kanban.sh (выполняется в запущенном контейнере app)
./kanban.sh passwd <логин> <новый-пароль>

# или бинарём напрямую (сервер не стартует); БД резолвится так же, как у приложения
kanban -reset-user <логин> -reset-password <новый-пароль> -db <тот же -db> -data-dir <тот же -data-dir>
```

Если пользователь существует — меняется его пароль; если нет — создаётся
**администратор** с таким именем. Пароль — не короче 6 символов. Так можно
вернуть доступ после restore, затем войти и сбросить пароли остальным из UI.

## Модель доступа по проектам

Доступ к контенту организован вокруг **проектов**. Проект — это контейнер с собственными **участниками** и **ролями**:

| Роль в проекте | Возможности внутри проекта |
|----------------|----------------------------|
| **Admin**      | Управление проектом, его участниками и настройками |
| **Editor**     | Создание и редактирование контента |
| **Viewer**     | Доступ только для чтения |

У каждого проекта есть настройка **видимости**:

- **Открытый** — неявно доступен всем пользователям; пользователи, не являющиеся явными участниками, получают доступ только для чтения (viewer)
- **Ограниченный** — доступ только указанным участникам

**Глобальные администраторы** имеют доступ ко всем проектам независимо от членства и видимости.

Эта модель доступа управляет функциями, привязанными к проектам: **доской канбан**, **пространствами вики** и **календарями проектов**.

## Восстановление пароля

Доступно для пользователей с привязанным Telegram-аккаунтом:

1. На странице логина нажмите «Забыли пароль?»
2. Введите имя пользователя
3. Бот отправит 8-значный код подтверждения
4. Введите код и установите новый пароль

## LDAP / Active Directory

Приложение поддерживает аутентификацию через LDAP/AD для корпоративных сред.

Настройка через API (admin):

```
POST /api/auth/sso/config
```

Параметры конфигурации:
- URL LDAP-сервера
- Base DN для поиска пользователей
- Bind DN и пароль (для поиска)
- Фильтр поиска пользователей
- Маппинг атрибутов

При LDAP-аутентификации пользователь вводит корпоративные учётные данные, и приложение проверяет их через LDAP-сервер.

## OpenID Connect (OIDC)

Поддержка SSO через OIDC-провайдеров (Keycloak, Google, Azure AD и др.).

Настройка через API (admin):

```
POST /api/auth/sso/config
```

Параметры:
- Client ID и Client Secret
- URL провайдера (issuer)
- Redirect URI

После настройки на странице логина появляется кнопка SSO-входа. При первом входе через OIDC автоматически создаётся локальный аккаунт.

Эндпоинты:
- `POST /api/auth/oidc/login` — начало OIDC-авторизации
- `POST /api/auth/oidc/callback` — обработка ответа провайдера
