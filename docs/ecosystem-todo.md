# Ecosystem — упорядоченный план выполнения

Единый чеклист оставшихся работ в оптимальном порядке. Выполняется сверху вниз,
каждый пункт = отдельный коммит (или несколько). Отмечать `[x]` по мере готовности.
Контекст и нюансы — в `ecosystem-plan.md`; правила — память `kanban-ecosystem-*`.

Принцип порядка: сначала дешёвое сквозное укрепление и инфраструктура (низкий риск,
польза копится) → доводка Календаря → Почта (внутренняя раньше внешней, т.к. в песочнице
нет сети) → финальная полировка всей экосистемы.

---

## Stage 1 — Сквозное укрепление и инфраструктура
- [ ] **S1.1** Глобальный chat-SSE: открывать `EventSource` при логине и закрывать при
  logout; бейдж непрочитанного обновляется до первого входа в чат (остаток A3).
- [ ] **S1.2** Обобщить SSE-хаб: вынести `sseHub`/`sseEvent` из `chat.go` в общий
  `internal/handler/events.go`, сделать payload пригодным для любых сервисов; чат — на него же.
- [ ] **S1.3** JSON экспорт/импорт сервисов (§1.8): расширить `model.ExportData` и
  `ExportAll`/`ImportAll` на wiki (spaces/pages/revisions/members), chat (channels/members/messages),
  calendar (calendars/events). Тесты round-trip.

## Stage 2 — Доводка Календаря (Phase B enhancements)
- [ ] **S2.1** Live-обновления календаря через общий SSE (создание/правка/удаление событий).
- [ ] **S2.2** Напоминания: шедулер (как `runBackupScheduler`) сканирует ближайшие события,
  шлёт in-app + Telegram уведомления; бейдж ближайших на rail (`setRailBadge('calendar', n)`).
- [ ] **S2.3** Вид «день» + перетаскивание событий мышью (frontend).

## Stage 3 — Почта (Phase C), от внутренней к внешней
- [ ] **S3.1** C1 хранилище/модель: ящики, папки (Inbox/Sent/Drafts/Trash/кастом),
  письма (RFC 5322: заголовки, text/html тело, флаги Seen/Flagged/Answered/Deleted),
  треды (in_reply_to/references), вложения (через `files`). Store + миграции + тесты.
- [ ] **S3.2** Внутренняя почта (работает без сети): web-API `/api/mail/*` + `mail.js`
  (папки, список, тред-вид, композер с вложениями, поиск, бейдж непрочитанных); отправка
  между пользователями системы. HTML-тела через `sanitize.go`; вложения — в `CleanupOrphanFiles` (§1.7).
- [ ] **S3.3** C2 SMTP-приём входящих (`emersion/go-smtp` + `go-message`): парсинг MIME,
  раскладка по ящикам, лимиты, antispam-hook. Локальный тест петлёй.
- [ ] **S3.4** C3 SMTP-отправка наружу: очередь, доставка на MX, ретраи, bounce; локальный sink для тестов.
- [ ] **S3.5** C5 безопасность доставки: TLS (STARTTLS), SPF-проверка входящих, DKIM-подпись
  исходящих, DKIM/DMARC-проверка. (DNS-записи — вне кода, при развёртывании.)
- [ ] **S3.6** C4 IMAP-доступ (опц., `emersion/go-imap`) либо только web-API — решение в начале.
- [ ] **S3.7** C7 e2e почты: юнит MIME/DKIM/очередь, локальная петля приём→ящик→веб-клиент.

## Stage 4 — Полировка экосистемы (Phase D)
- [ ] **S4.1** Глобальный поиск по всем сервисам (канбан/wiki/чат/календарь/почта) в едином окне.
- [ ] **S4.2** Единый центр уведомлений (все типы: упоминания, события, письма, задачи).
- [ ] **S4.3** Полный i18n-свип: переводы chat/calendar/mail во все 10 языков (сейчас ru/en, остальные — англ. фолбэк).
- [ ] **S4.4** Сверка единообразия UI/UX, тем, RTL во всех сервисах.
- [ ] **S4.5** Документация: README + `docs/en|ru` под экосистему.
