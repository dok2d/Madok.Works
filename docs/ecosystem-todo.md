# Ecosystem — упорядоченный план выполнения

Единый чеклист оставшихся работ в оптимальном порядке. Выполняется сверху вниз,
каждый пункт = отдельный коммит (или несколько). Отмечать `[x]` по мере готовности.
Контекст и нюансы — в `ecosystem-plan.md`; правила — память `kanban-ecosystem-*`.

Принцип порядка: сначала дешёвое сквозное укрепление и инфраструктура (низкий риск,
польза копится) → доводка Календаря → Почта (внутренняя раньше внешней, т.к. в песочнице
нет сети) → финальная полировка всей экосистемы.

## Stage 3 — Почта (Phase C), от внутренней к внешней
- [x] **S3.1** C1 хранилище/модель: mail_messages/mail_box/mail_attachments, треды, флаги,
  папки, поиск; экспорт + GC вложений; тесты. (feat(mail) S3.1)
- [x] **S3.2** Внутренняя почта: `/api/mail/*` + `mail.js` (папки, список, тред, композер с
  вложениями, reply/quote, поиск, бейдж, SSE, sanitize, уведомления). Сервис включён. (feat(mail) S3.2)
- [x] **S3.3** C2 SMTP-приём входящих (`go-smtp`+`go-message`), за флагом `-smtp-addr` (по умолч. выкл);
  MIME-парсинг + вложения + маппинг по local-part; тест. (feat(mail) S3.3)
- [ ] **S3.4** C3 SMTP-отправка наружу — ⚠️ DEPLOY-ONLY: код реализуем, но реальную доставку на MX
  нельзя проверить в песочнице (нет исходящего :25/публичной сети). Отложено до развёртывания.
- [ ] **S3.5** C5 TLS + SPF/DKIM/DMARC — ⚠️ DEPLOY-ONLY (нужны DNS-записи, публичный IP, сертификаты).
  Кандидат на частичную реализацию: DKIM-подпись с самопроверкой в unit-тесте.
- [ ] **S3.6** C4 IMAP-доступ — опц., крупный; веб-API уже покрывает работу с почтой. Отложено.
- [ ] **S3.7** C7 e2e внешней почты — зависит от S3.4–S3.6 (deploy). Внутренняя петля уже покрыта тестами.

> Итог Stage 3: **рабочая почта доставлена** (внутренняя + входящий SMTP, всё проверено).
> Внешняя доставка/DKIM/IMAP помечены DEPLOY-ONLY — их нельзя валидировать в песочнице
> (см. ecosystem-plan §5 caveat), поэтому не реализуются «вслепую», чтобы не было «для галочки».
