# Ecosystem — упорядоченный план выполнения

> **Статус: ПЛАН ЗАВЕРШЁН (2026-06-15).** Все пункты, выполнимые в песочнице,
> реализованы, протестированы и закоммичены. Оставшиеся `[ ]` — это DEPLOY-ONLY
> работы (внешний MTA: отправка/DKIM/SPF/DMARC, IMAP, e2e внешней почты), которые
> требуют реальной сети/DNS/сертификатов и сознательно не делаются «вслепую».
> Сверх исходного плана реализован крупный пласт доработок — см. раздел
> «После плана» внизу.

Единый чеклист оставшихся работ в оптимальном порядке. Выполняется сверху вниз,
каждый пункт = отдельный коммит (или несколько). Отмечать `[x]` по мере готовности.
Контекст и нюансы — в `ecosystem-plan.md`; правила — память `kanban-ecosystem-*`.

Принцип порядка: сначала дешёвое сквозное укрепление и инфраструктура (низкий риск,
польза копится) → доводка Календаря → Почта (внутренняя раньше внешней, т.к. в песочнице
нет сети) → финальная полировка всей экосистемы.

## После плана — доработки сверх исходного чеклиста ✅

Реализовано после закрытия Stage 1–4 (каждый пункт — отдельные коммиты на ветке
`feature/ecosystem`):

- **Безопасность.** Полный аудит экосистемы (`docs/security-audit.md`); закрыты A1–A5
  (CSRF/Origin, SSRF исходящего SMTP, rate-limit входящего, self-XSS превью, коллизии
  алиасов) и M1–M4 (CRLF-инъекции, slowloris, backscatter, relay-abuse).
- **Wiki.** Редактор переведён на **только Markdown** с живым предпросмотром и панелью
  форматирования (заголовки/списки/код/ссылка/картинка/таблица через grid-пикер/выноски);
  визуальный (WYSIWYG) режим убран; lossless-правки; выбор пространства в шапке.
- **Чат — вид «как Telegram».** Пузыри, аватары-инициалы, ответы (цитаты), эмодзи-реакции,
  закрепления (+бар), меню действий «⋯», индикатор «печатает…», галочки прочтения в ЛС,
  системные сообщения, список ЛС со всеми контактами, сортировка по последнему сообщению,
  вложения. Бэкенд: pins/reactions/replies/typing/read + системные сообщения.
- **Календарь.** Виды и список календарей в шапке; **подписки на внешние ICS/iCal-ленты**
  (например, Google Calendar) — read-only, per-user, периодическая синхронизация, SSRF-guard.
- **Почта.** Папки + «Написать» в шапке; двухпанельный перетаскиваемый интерфейс; правила
  распределения в настройках; антиспам/аудит/алиасы/настройки сервера в админке.
- **UX/настройки.** Контекстные шапки по сервисам (стиль фильтров канбана); **единая
  страница настроек** с ролевыми вкладками; **брендинг** (имя приложения → title/шапка/
  бэкапы); сервисы **включаются/выключаются и переупорядочиваются** (включая саму
  канбан-доску), с гарантией на сервере; Telegram перенесён в «Интеграции».
- **Документация.** README (en/ru) и `docs/{ru,en}/{ecosystem,configuration,api,user-guide}.md`
  приведены к текущему состоянию.
