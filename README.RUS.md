# Madok.Works — командное рабочее пространство вокруг канбана

[English version](README.md)

**Madok.Works** — self-hosted рабочее пространство для команды вокруг канбан-доски, теперь — полноценная **экосистема**: проекты со своей доской + wiki, чат, звонки, календарь и почта под одним интерфейсом, в одном бинарнике и одном файле SQLite (PostgreSQL опционально).

## Проекты

Верхний уровень — **Проект**: самодостаточный контейнер со своей канбан-доской, wiki-пространствами и календарями. Из коробки есть проект по умолчанию («Общее»); новые создаются из селектора проектов в шапке. У проектов есть открытая или ограниченная видимость и роли на проект (админ/редактор/читатель). Задачи нумеруются в рамках проекта как **KEY-123**, теги тоже привязаны к проекту. Модерация проектов — в **Настройки → Доска → Проекты**. Календарь сквозной (cross-project), поэтому дедлайны и спринты из всех проектов сходятся на одной шкале времени.

## Сервисы экосистемы

Помимо канбан-доски, опциональные сервисы используют общие авторизацию, роли, уведомления, поиск, темы и i18n. На вкладке **«Сервисы»** администратор может включать/выключать каждый сервис (включая саму доску) и менять их порядок на панели сервисов; выключенный сервис блокируется и на сервере, а не просто скрывается. Каждый сервис добавляет в шапку свои селекторы (в стиле фильтров канбана), а единый глобальный **многословный поиск** (должны совпасть все термины) охватывает задачи, комментарии, wiki, чат, календарь и почту, с фильтром по области (сервису).

- **Wiki** — пространства в стиле Confluence: дерево страниц, markdown-редактор с панелью форматирования, история ревизий и роли на пространство (админ/редактор/читатель). Поддерживаются @упоминания, `[[ссылки]]` с обратными ссылками (backlinks), авто-якоря заголовков, `[[toc]]`, ссылки на задачи, комментарии с реакциями, шаблоны страниц, встроенные диаграммы draw.io (в комплекте) и экспорт в Markdown/PDF.
- **Чат** — мессенджер в стиле Telegram: пузыри, аватары, реакции, ответы, закрепления, индикатор печати и галочки прочтения в ЛС, список контактов. Публичные каналы, **каналы только для чтения**, **приватные группы** (с выбором участников) и личные сообщения с live-обновлениями (SSE), @-упоминаниями, выбором эмодзи, вставкой Markdown и изображений с лайтбоксом, **звуком уведомлений с отключением по каналам**, поиском и счётчиками непрочитанного.
- **Звонки** — встроенные голосовые/видеозвонки на **WebRTC**: 1:1 и небольшие групповые mesh-звонки с сигналингом через SSE+POST, UI вызова, переключение микрофона и камеры, приглашение любого участника прямо во время звонка. Используется встроенный STUN-сервер плюс опциональный self-hosted TURN (coturn), настраиваемый в настройках.
- **Календарь** — личные/общие календари, повторяющиеся события (RRULE), виды месяц/неделя/день/повестка, напоминания, сквозное (cross-project) наложение дедлайнов задач и спринтов, а также подписки на внешние ICS/iCal-ленты только для чтения (например, Google Calendar).
- **Почта** — внутренняя почта между пользователями из коробки: папки в шапке, двухпанельный вид, треды, вложения, поиск, правила распределения, антиспам и алиасы. Опциональный приём входящего SMTP через `-smtp-addr`, а также внешняя отправка/DKIM, настраиваемые на вкладке «Почтовый сервер» (см. документацию).
- **Файлы** — общее файловое хранилище инстанса (как сетевая шара): дерево папок с хлебными крошками, мультизагрузка с drag-and-drop, переименование/перемещение, предпросмотр картинок и текста и **публичные ссылки** (токен-URL работает без входа; ссылку можно отозвать, при выключенном сервисе она гаснет). Загрузки подчиняются настраиваемой политике типов файлов; read-only пользователи могут просматривать и скачивать.

## Почему Madok.Works

- **Минимум зависимостей** — Go + SQLite в основе, никаких Redis и очередей сообщений; PostgreSQL поддерживается, но опционален
- **Одна команда для запуска** — `./kanban.sh up --build`, открыть браузер
- **Всё включено** — проекты, спринты, эпики, теги по проектам, вложения, Markdown, комментарии с @упоминаниями, многословный поиск (текст + regex), drag-and-drop, уведомления в Telegram, **2FA (TOTP)**, журнал аудита
- **Интеграции** — Git (GitHub/GitLab/Gitea): входящие вебхуки связывают коммиты/ветки/MR с задачами по KEY-123/#123 и могут автоматически перемещать задачи при merge; Telegram-бот с учётом проектов
- **Безопасность из коробки** — rootless Podman, read-only FS, все capabilities сброшены; ограничить локальным интерфейсом — `--app-bind 127.0.0.1`
- **Работает офлайн** — все статические ресурсы локальные, без обращений к внешним CDN
- **8 тем, 10 языков** — dark/light/ocean/forest/nord/dracula/solarized/spacedust, от русского до арабского

## Быстрый старт

Стек (приложение + PostgreSQL) поднимается через podman-compose; `./kanban.sh` — тонкая обёртка, превращающая флаги в переменные, которые читает compose-файл:

```bash
./kanban.sh up --build
# → http://<LAN-IP>:10010   (первый визит — создание администратора)
```

Порты, имя проекта и доступы к БД задаются флагами (значения по умолчанию — из `deploy/.env`):

```bash
./kanban.sh up --app-port 8080 --db-port 5433 -p work     # свои порты + имя проекта
./kanban.sh up --app-bind 127.0.0.1                       # только локально (например, за reverse-proxy)
./kanban.sh up --db "postgres://kanban:kanban@db:5432/kanban?sslmode=disable"  # форсить Postgres сразу
./kanban.sh logs            # логи приложения  (logs db — для Postgres)
./kanban.sh backup          # pg_dump → backups/
./kanban.sh down            # остановить (данные сохраняются) ·  ./kanban.sh wipe  удаляет тома
```

При первом запуске страница настройки создаёт администратора и опционально предлагает переключиться на встроенный PostgreSQL; иначе остаётся SQLite. `./kanban.sh` без аргументов — полный список команд.

Сборка образа скачивает встроенный редактор draw.io (~50 МБ с GitHub releases). Если эта загрузка на вашей сети падает (`curl` exit 56), либо один раз положите файл в `vendor-cache/draw.war` (см. `vendor-cache/README`), либо соберите без него:

```bash
./kanban.sh build --skip-drawio     # вики работает; диаграммы — только через внешний drawio_url
```

За nginx с TLS (приложение на localhost, 443 терминирует хост): обёртка сама генерирует nginx-конфиг и systemd-юнит (БД остаётся внутренней):

```bash
./kanban.sh up --app-bind 127.0.0.1 --app-port 10010 -p s4m-works --build
./kanban.sh deploy -p s4m-works --app-port 10010 --host mw.example.com   # systemd-юнит + nginx-конфиг
# (./kanban.sh nginx … / ./kanban.sh systemd … — только одно из двух)
```
Сгенерированный nginx-конфиг пробрасывает Host (для same-origin проверки), поднимает лимит тела (`client_max_body_size 64m` под импорт бэкапа) и отключает буферизацию для SSE (живой чат/календарь/звонки).

## Возможности

| Область | Что получаете |
|---------|--------------|
| Проекты | Многопроектные контейнеры верхнего уровня, у каждого своя доска, wiki и календари; роли на проект; задачи с ключами KEY-123 |
| Доска | Колонки с drag-and-drop, инлайн-редактирование, приоритеты, дедлайны |
| Планирование | Спринты (план → активный → завершён), эпики с цветами и прогрессом |
| Совместная работа | Вложенные комментарии, @упоминания, подписки на задачи, лента активности |
| Организация | Теги по проектам, зависимости (блокирует / зависит от), TODO-чеклисты |
| Поиск | Многословный текстовый и regex-поиск по задачам, комментариям, wiki, чату, календарю и почте, с областью по сервису |
| Файлы | Вложения, вставка изображений (Ctrl+V), Markdown с подсветкой синтаксиса |
| Уведомления | В приложении + Telegram-бот с учётом проектов (назначения, упоминания, обновления) |
| Интеграции | Git (GitHub/GitLab/Gitea): вебхуки связывают коммиты/ветки/MR с задачами, авто-перемещение при merge |
| Безопасность | 2FA (TOTP, опционально), журнал аудита, три роли: Администратор, Пользователь, Только чтение; роли на пространство в wiki |
| Экосистема | Wiki, Чат, Звонки (WebRTC), Календарь, Почта — включаемые и переупорядочиваемые сервисы в одном интерфейсе |
| Настройки | Единая страница настроек с ролевыми вкладками, открывается с панели сервисов |
| Данные | JSON экспорт/импорт (включая сервисы экосистемы), бэкапы по расписанию через `./kanban.sh backup` |
| Кастомизация | Название приложения / брендинг, 8 тем, 10 языков, настраиваемый шрифт, выбор часового пояса |

Madok.Works не пытается заменить Jira для компании на 500 человек. Он создан для отдельных разработчиков и небольших команд, которым нужно быстрое, приватное, self-hosted рабочее пространство, работающее из коробки без инфраструктурных затрат.

## Стек

- **Go 1.22** — stdlib `net/http`, без фреймворков
- **SQLite** — единственная зависимость `mattn/go-sqlite3` (PostgreSQL опционально через `-db postgres://…`)
- **Vanilla JS** — без React, Vue и шага сборки
- **Podman** — rootless контейнер с хардингом безопасности
